# NodeWave website

The site of [nodewave.org](https://nodewave.org): plain HTML, CSS and a little JavaScript, no build step and no server. The app itself lives in [sputlab/nodewave](https://github.com/sputlab/nodewave); the project documents and the changelog are there.

## Pages and files

- `index.html`: home page (hero, numbers bar, screenshot carousel, features, timeline, security, download)
- `devices.html` + `devices.json`: searchable, filterable list of the tested phones (format below), what has been verified, and what has not; also where to offer a phone
- `blog.html` + `posts.json`: the blog (format below)
- `test-report.html`: the test list and the report form. The report is composed in the browser and sent with a `mailto:` link to testreport@nodewave.org (the site has no server), with copy and download as fallbacks
- `support.html`: ways to support the project, as accordions (lend devices, run tests, report problems, spread the word, join communities, contribute code, donate)
- `donate.html`: PayPal donation page, adapted from sputlab.com/donate (no donor list: that would need a server)
- `transparency.html` + `transparency.json`: public ledger of money received and spent, and of contributions in kind (format below)
- `style.css`, `site.js`: shared styles and scripts (carousel, timeline, mobile menu, numbers bar). `?reveal=all` shows every timeline item at once, for previews
- `stats.json`: the numbers bar data (first commit date, releases, unit tests). It is **regenerated by the workflow** from the app repository on every deploy, so do not edit it by hand
- `images/logo_new.png`: the app icon; `assets/screens/`: the screenshots
- `CNAME`: the custom domain `nodewave.org` (GitHub Pages reads it from here)
- `.nojekyll`: serve the files as they are

The top menu holds Screens, Features, Timeline, Get it, Devlog and the Support button; Devices and Test report are reached from the footer, the home page and the Support page. The header and the footer links are repeated in every HTML page. When you add or rename a page, update them in all pages.

## Run it locally

```
python3 -m http.server
```

then open http://localhost:8000. Use a local server rather than opening the files directly: `transparency.json`, `devices.json`, `posts.json` and `stats.json` are loaded with `fetch`, which browsers block on `file://`.

## Publishing

`.github/workflows/pages.yml` publishes the site to GitHub Pages on every push to `main`, once a day (to refresh the numbers bar) and on manual run. It checks out the app repository to compute `stats.json`, then uploads the site. The Pages setting must be *Settings -> Pages -> Build and deployment -> Source: GitHub Actions*.

DNS for the custom domain: an `A` record set pointing `nodewave.org` to GitHub Pages (185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153) and a `CNAME` record `www` pointing to `sputlab.github.io`; then tick *Enforce HTTPS* in Settings -> Pages.

## Updating the transparency ledger

Edit `transparency.json` and commit; the page recomputes the totals itself. Every change stays visible in the Git history. The file has two lists:

```json
{
  "currency": "EUR",
  "money": [
    { "date": "2026-11-12", "type": "in",  "description": "Donation via PayPal", "amount": 10.00 },
    { "date": "2026-11-12", "type": "out", "description": "PayPal fee on the donation above", "amount": 0.64 },
    { "date": "2026-11-15", "type": "out", "description": "Domain nodewave.org, 1 year", "amount": 12.00, "url": "https://example.com/receipt" }
  ],
  "inKind": [
    { "date": "2026-11-20", "what": "Pixel 6", "from": "Mario R.", "usedFor": "Android 14 testing" }
  ]
}
```

`money` entries (cash received and spent):

| Field | Required | Meaning |
|---|---|---|
| `date` | yes | `YYYY-MM-DD`; entries are shown newest first |
| `type` | yes | `"in"` for money received, anything else (use `"out"`) for an expense |
| `description` | yes | what it was; donors are not named unless they ask |
| `amount` | yes | a positive number in euro, with a dot as decimal separator (`12.50`), never negative and never a string |
| `url` | no | link to a receipt or proof, shown as "proof" |

`inKind` entries (things given, not money, so they do not enter the totals):

| Field | Required | Meaning |
|---|---|---|
| `date` | yes | `YYYY-MM-DD` |
| `what` | yes | the device, hardware or service |
| `from` | yes | who gave it, only with their permission |
| `usedFor` | yes | what it is used for |

The JSON must stay valid (no trailing commas, double quotes only). If it does not parse, the page shows an error pointing to the raw file.

## Adding a tested device

Add an object to the `devices` array of `devices.json`; the list sorts itself and the filters are built from the values present.

```json
{ "brand": "Google", "model": "Pixel 6", "code": "GB7N6", "android": 14, "skin": "Stock", "tester": "Community", "notes": "Works with the screen off." }
```

`brand`, `model`, `android` (a number) and `notes` are shown and searched; `code` and `skin` are optional (use `""` when unknown); `tester` is for the record ("Project" or "Community").

## Writing a blog post

You can write posts with the offline editor: open `tools/post-editor.html` in a browser (no server needed), load `posts.json`, edit, then download the new `posts.json` and replace the file. The format it produces is described below.

Add an object to the `posts` array of `posts.json` (newest first is not required, the page sorts by date). Each post has a unique `id` (used for the link `blog.html#id`), a `date` (`YYYY-MM-DD`), a `title` and a `body`, a list of blocks:

```json
{
  "id": "release-0-13",
  "date": "2026-11-20",
  "title": "NodeWave 0.13",
  "body": [
    "A paragraph. It can contain a [link](https://nodewave.org), **bold** and *italic* text.",
    { "heading": "What is new" },
    { "list": ["First item", "Second item with a [link](support.html)"] },
    { "img": "assets/screens/sam_10_map_nodes.png", "alt": "The offline map", "caption": "Optional caption, links allowed." }
  ]
}
```

A block is a plain string (paragraph), `{"heading": ...}`, `{"list": [...]}` or `{"img": path, "alt": ..., "caption": ...}`. Images go in `assets/` and are referenced by relative path. HTML is not interpreted: anything that is not the markup above is shown as plain text. Only `http(s):`, `mailto:` and relative links are accepted.

## Keeping it in step with the app

When a release changes behaviour, update the timeline and the feature cards on the home page, the test catalogue in `test-report.html` (the `GROUPS` array and `APP_VERSIONS`), and `devices.html` if the tested phones or what has been verified changed.
